# Android TV visualizer and Search navigation design

Draft for review · 2026-11-23 · Milkbeat baseline `630dc542`

The two bug fixes are the priority. Listeners should be able to leave the TV remote idle while they watch ProjectM during playback, and reach the current track from Search with the D-pad. The brightness limiter is an independent, optional feature for watching bright presets in a dark room. The behavior and UI choices below are proposals.

## 1. Keep Android TV Ambient Mode out of an active visualizer session

**Current path.** `FlowTvApp` mounts the expanded music player or the browsing shell. `TvMusicNowPlayingBackdrop` mounts ProjectM only for the displayed visualizer layer. It retains that layer under the loading indicator until the matched video is ready to replace it. `TvVisualizerBackground` manages the lifecycle of the embedded `VisualizerView`, and the renderer can drift on silence when the user pauses. The separate `TvPlayerScreen` uses `KeepScreenOnEffect`. The embedded ProjectM path has no screen-on request in Milkbeat. [TV root](../../../app/src/main/java/io/github/aedev/flow/ui/tv/FlowTvApp.kt#L230) · [Backdrop](../../../app/src/main/java/io/github/aedev/flow/ui/tv/music/TvMusicNowPlayingBackdrop.kt#L25) · [Visualizer lifecycle](../../../app/src/main/java/io/github/aedev/flow/ui/tv/music/TvVisualizerBackground.kt#L33) · [TV video player](../../../app/src/main/java/io/github/aedev/flow/ui/tv/screens/TvPlayerScreen.kt#L120)

Android TV allows screen-on for user-initiated playback with moving visuals. Use the standard foreground keep-screen-on mechanism while ProjectM is displayed and music is playing. A track the listener starts with Visualizer already selected qualifies, as do subsequent tracks in that listening session. Allow Ambient Mode again when playback is paused, ended, stopped, suppressed or fatally stalled. Android TV power and Energy Saver settings still apply. [Android TV Ambient Mode](https://developer.android.com/training/tv/playback/ambient-mode) · [Keep the screen on](https://developer.android.com/develop/background-work/background-tasks/awake/screen-on)

| Foreground state | ProjectM requests screen-on |
| --- | --- |
| ProjectM visible and user-initiated playback active | Yes, with controls shown or hidden and with Queue or Mood mix open over the moving backdrop |
| Match preparing over visible ProjectM while audio plays | Yes, through the first-frame handoff |
| Brief audio buffering after active playback began, with Media3 still intending to play and playback unsuppressed | Retain the held request for up to 30 seconds from the start of that buffering episode. Release on timeout and reacquire when audio plays again |
| Initial audio load or screen opened while paused, with visuals drifting on silence | No |
| Artwork, a matched video after it replaces ProjectM, a collapsed player, Search, other browsing, or missing/failed visualizer surface | No ProjectM request |
| Activity stopped, screen off, view detached, playback paused, ended, stopped, suppressed or failed | Release immediately |

**Ownership.** Prefer `View.keepScreenOn` on the attached ProjectM view. The view is scoped to the actual backdrop and has the same screen-on semantics as the Android window flag. Read only playback changes that affect the decision. Use Media3 events to capture play intent, suppression and buffering coherently if the existing music state cannot supply them. In this baseline, the music manager updates `isPlaying`, `isEnded` and `isBuffering`, but its update path does not populate `playWhenReady`. Use one cancellable timeout per buffering episode and cancel it on playback resumption, pause, stop, replacement or detach. Controls visibility, progress updates and renderer frames need no screen-on logic. Clear the view request when the host stops or closes and reevaluate on foreground reentry. Activity-wide ownership would require coordinating independent video and visualizer writers, so the view-scoped request is the smaller change. [Music manager](../../../app/src/main/java/io/github/aedev/flow/player/EnhancedMusicPlayerManager.kt#L386) · [Android view and window options](https://developer.android.com/develop/background-work/background-tasks/awake/screen-on)

Explicit sleep or Home still takes the listener out of the visualizer. The separate TV video player retains its current screen-on policy. This change gives no screen-on policy to the matched music-video surface after it replaces ProjectM.

## 2. Return from Search to Now Playing with the D-pad

**Current path.** For an active music session, `TvShell` renders `TvNowPlayingStrip` below the navigation host and already has a requester attached to the strip’s track card. Center on the card takes the existing expand path. The Search destination receives no explicit downward target. Search combines a text field with custom arrow handling, lazy chip rows, recent searches and a paged lazy results list. The shell restores strip focus when the expanded player closes. The missing directional contract is visible in source. The exact focused item, key consumption and lazy-list state in the reported trap still need a remote reproduction. [Shell layout and restoration](../../../app/src/main/java/io/github/aedev/flow/ui/tv/TvShell.kt#L107) · [Search route](../../../app/src/main/java/io/github/aedev/flow/ui/tv/navigation/TvNavHost.kt#L97) · [Search layout](../../../app/src/main/java/io/github/aedev/flow/ui/tv/screens/search/TvSearchScreen.kt#L134) · [Text field keys](../../../app/src/main/java/io/github/aedev/flow/ui/tv/components/TvSearchField.kt#L122) · [Result list](../../../app/src/main/java/io/github/aedev/flow/ui/tv/screens/search/TvSearchResults.kt#L107) · [Strip track card](../../../app/src/main/java/io/github/aedev/flow/ui/tv/components/TvNowPlayingStrip.kt#L91)

| Where the listener is | Expected remote behavior |
| --- | --- |
| Search results or recent searches | Down traverses the content. Down through the lower boundary moves to the strip’s track card. A loading placeholder, nonfocusable row or pending page cannot trap focus. |
| Blank, loading, no results or error, with usable Search controls | Down from the lowest actionable chip or input group reaches the card when nothing else below can receive focus. Results arriving later leave focus with the listener. |
| No searchable sources and no focusable Search content | With an active strip, entering Search content from the rail lands on the track card. With no strip, the rail remains a safe focus target. |
| On-screen keyboard open | The keyboard owns its D-pad navigation. Dismiss it with Back or submit, then use Down in Search. Center on the track card opens the current player. |
| On the track card | Center expands the same session and shows its current backdrop. Left and Right retain their normal strip behavior. Up returns to the last valid Search target or the nearest valid Search control, preferring the source chip or the query field when results disappeared. The rail remains reachable if Search has no focusable content. |
| Back from the expanded player | Back follows the existing order for dismissing scrubbing, panels and controls. When the player collapses, return to Search and focus the track card. Up returns to Search content. Keep the query and selected source/filter, and restore result position where the same results are still available. |
| Track absent or dismissed | Omit the cross-region focus edge. If the strip disappears while focused, recover to available Search content or the rail. |

**Focus contract.** The shell owns the optional strip focus target and passes it through `TvNavHost` to Search only while the card is mounted. Use direction-aware Compose focus properties and a Search content boundary, preserving normal traversal inside the field, chips and lists. Give the boundary an explicit Down exit to the track card. If the lazy list’s search consumes Down first, wire the focus exit at the terminal actionable item or logical row. Derive that boundary from reachable results, including nested shelves/grids and provider actions such as Show all. Hold a terminal-row exit stable while that row remains focused so an append cannot move the exit out from under a remote press. Coming back Up allows the listener to continue into any new rows. Take the exit even when another page is pending, and give focus to the strip’s body before its transport or dismiss buttons.

Use a Search-scoped focus restorer or stable item key plus a fallback for Up, with saved query/source/filter and scroll state scoped to the Search back-stack entry where needed across shell collapse. On async query changes, resolve targets against the displayed results. Route only attached targets, and retain ordinary navigation if focus transfer fails. Keep the existing expand/collapse callbacks and Back behavior. A separate Search shortcut would add another focus stop, while a shell-wide Down handler would intercept keys that belong to the keyboard and other pages. [Compose focus traversal](https://developer.android.com/develop/ui/compose/touch-input/focus/focus-traversal) · [Compose focus groups](https://developer.android.com/develop/ui/compose/touch-input/focus/focus-group)

```text
Search content ── Down at lower focus boundary ──► Now Playing track card
Search content ◄─ Up ──────────────────────────── Now Playing track card
Track card ── OK ──► Full player ── Back until collapsed ──► Track card
```

## 3. Optional brightness limiter

**Proposed placement.** Add **Brightness limiter** in **Settings → Visualizations → Picture quality**, next to Frame rate and Detail. Reuse the existing remote-selectable side picker with **Off** (default), **75%**, **50%** and **25%**. Saving a value applies to the next visible ProjectM frame once the setting is read. The initial release uses Settings because the player already has a compact transport row with view, mood and queue actions. If in-player access becomes a frequent need, consider a labeled entry in a visualizer-specific side panel once the TV layout and focus order have been reviewed. Keep Mood mix’s existing **Brightness** filter for choosing presets. [Picture-quality settings](../../../app/src/main/java/io/github/aedev/flow/ui/tv/screens/settings/TvVisualizerSettingsPane.kt#L255) · [Player controls](../../../app/src/main/java/io/github/aedev/flow/ui/tv/music/TvNowPlayingControls.kt#L140) · [Mood mix](../../user-guide/visualizer.md#mood-mix)

**Setting contract.** Store an integer in the existing `VisualizerPreferences` DataStore, per TV installation. Treat a missing or unsupported value as Off. Off uses the current render path. A percentage dims the full ProjectM picture uniformly, including white flashes and transitions, using the selected share of the original picture signal. The levels are relative image controls, with no calibration in nits or guarantee about physical panel brightness. At a fixed level the dark parts dim too. Apply it to the ProjectM fallback while matched video prepares. Artwork, the video picture and separate UI elements such as the title, cover, controls, focus indicators and loading spinner keep their own brightness. A paused but still visible visualizer also follows the saved level. [Preference store](../../../app/src/main/java/io/github/aedev/flow/data/local/VisualizerPreferences.kt#L19) · [Backdrop and loading indicator](../../../app/src/main/java/io/github/aedev/flow/ui/tv/music/TvMusicNowPlayingBackdrop.kt#L36)

**Rendering approach.** Try one static black compositing layer directly above the ProjectM surface and below the player UI, with opacity equal to one minus the selected level. Mount it in the same branch as ProjectM, with no input or accessibility participation and no animation. Consume the saved level at the backdrop, independently of engine settings that allocate or reload renderer state. The current ProjectM AAR uses a `GLSurfaceView`. `TvVisualizerHost` puts it above the preparing video surface with `setZOrderMediaOverlay(true)`, which still places it below the Android window. Android’s surface composition and device performance therefore need verification before shipping this approach. The latest published core was `v2.3.57` at design review, and its view/JNI entry points expose no output-brightness control. [Milkbeat surface order](../../../app/src/main/java/io/github/aedev/flow/ui/tv/music/TvVisualizerHost.kt#L79) · [Released VisualizerView](https://github.com/johnneerdael/ProjectM-TV/blob/v2.3.57/core/src/main/java/nl/neerdael/projectm/core/VisualizerView.java) · [Android SurfaceView composition](https://developer.android.com/reference/android/view/SurfaceView#setZOrderMediaOverlay(boolean))

If the compositor path alters the video handoff or costs enough to reduce sustained frame rate or adaptive resolution, the engine alternative is attenuation in the existing final display pass, after the preset blend and outside the feedback loop. That requires a reviewed ProjectM core change and AAR release. Defer the optional feature if neither path meets the device checks. A window brightness override would change the whole window, including text and controls, so it does not meet the setting contract. [Window brightness API](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#screenBrightness)

## Acceptance before shipping

| Area | Evidence to collect |
| --- | --- |
| Ambient Mode baseline | On a physical Android TV or Google TV with Ambient Mode enabled, measure the idle timeout on the same setup using Artwork or ordinary audio browsing. On the current build, record whether visible ProjectM reproduces the report and capture app version, TV model/OS, playback state and selected view. |
| Ambient Mode fix | With a track long enough to span the observed timeout, leave the remote untouched in ProjectM for that timeout plus at least one minute. Observe moving visuals and continuing audio. Pause, switch to Artwork, collapse into Search, press Home, and restore playback in separate checks. Verify screen-on ownership releases immediately on each in-app exit or pause and the control case enters Ambient Mode at its next eligible idle timeout. Test screen-off and foreground reentry and verify the separate video player still keeps the screen on during playback. Capture window/view state as supporting evidence. |
| Buffering and handoff | Verify initial buffering with no active audio, a brief mid-track rebuffer, a pause during rebuffer, prolonged buffering, and playback recovery. While a matched video prepares over visible ProjectM, verify the request persists until the rendered picture replaces ProjectM, or stays with ProjectM if preparation fails. Use deterministic callback/state coverage for timeout and teardown ordering. |
| Search with a real remote | Start a track, Back to browse, enter Search, type and dismiss the TV keyboard, and press Down through the results. Verify the focus ring lands on the track card and Center opens the same track and queue without a reload or seek. Back returns to the card, Up returns to Search. Repeat with blank Search, recent searches, empty/error/loading results, no sources, multiple result layouts, a pending page and a page arriving at the boundary. Check rapid direction presses and dismissal of the focused strip. Verify Search with no current track and navigating to other tabs. Use a local catalog for repeatability and a paged provider for the append case. |
| Brightness and performance | At matched presets, audio, display mode and frame samples, compare Off and every step on an SDR capture that includes the ProjectM surface. Check decreasing output on white, colored and near-black regions, stable UI brightness and no dimming of artwork/video after handoff. Check persistence, old installs, unsupported values, pause/foreground, and cut/blend/video-ready transitions. On a 4K TV and a lower-headroom supported TV, compare sustained frame pacing, adaptive resolution, thermals and buffer allocations with Off and 50%. Require equivalent playback/renderer behavior within the repeatability of each device baseline. |

## Delivery and documentation

Land the two fixes with focused coverage and one planned physical-TV acceptance session after build validation. The settings feature can follow independently.
